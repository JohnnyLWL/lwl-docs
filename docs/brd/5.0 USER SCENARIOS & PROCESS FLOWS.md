5.0 USER SCENARIOS & PROCESS FLOWS
5.1 Purpose
This section describes how Living With Lolo's Consolidated Client Communications Hub will manage day-to-day communications between clients and the internal team. Each scenario reflects a business workflow—independent of technical implementation—showing how client interactions are received, routed, responded to, tracked, and archived.
The goal is to ensure that every client communication is acknowledged, assigned, visible, and preserved, while eliminating duplication, missed responses, and uncertainty about ownership.
5.2 SCENARIO 1: EMAIL COMMUNICATION FLOW
Objective: Ensure every client email is received, routed, and responded to efficiently, with full visibility and the ability to distinguish between active and resolved communications.
Actors: Client → Shared Email Inbox (Gmail) → HubSpot Interface → Primary POC → Backup POC → Client
Process Flow:
5.2.1 Inbound Message
5.2.1.1 The client sends an email to the centralized address (e.g., VIP@livingwithlolo.com).
5.2.1.2 The message is synced with Gmail and the system identifies the client and project using the sender's address.
5.2.2 Routing
5.2.2.1 The system assigns the message to the Primary POC for the associated project.
5.2.2.2 All team members with appropriate permissions can view the message thread in real time.
5.2.2.3 The assigned POC receives notification (mobile push, desktop alert, or email based on their preferences).
5.2.3 Response
5.2.3.1 The POC replies directly through the HubSpot interface.
5.2.3.2 The client receives the response from the shared Living With Lolo address (VIP@livingwithlolo.com).
5.2.4 Resolution
5.2.4.1 Once the matter is handled, the POC marks the conversation Closed.
5.2.4.2 Closed conversations remain visible to the entire team for transparency and audit.
5.2.4.3 The Backup POC monitors Closed conversations as part of their daily quality assurance checks.
5.3 SCENARIO 2: SMS (TEXT MESSAGE) COMMUNICATION FLOW
Objective: Centralize all client text messaging into one shared HubSpot-managed number, ensuring consistent visibility and brand voice.
Actors: Client → HubSpot SMS Add-On → Primary POC → Backup POC → Client
Process Flow:
5.3.1 Inbound Message
5.3.1.1 Client sends an SMS to the Living With Lolo business number managed via HubSpot SMS Access Add-On.
5.3.1.2 Message appears in HubSpot Conversations Inbox, automatically linked to the client and project record.
5.3.1.3 Notification sent to Primary POC.
5.3.2 Routing
5.3.2.1 If the Primary POC is Out of Office (Vacation Flag enabled), routing automatically diverts to the Backup POC.
5.3.2.2 All team members can view message history for that client and project.
5.3.3 Response
5.3.3.1 The POC replies directly via HubSpot using the shared business number.
5.3.3.2 SMS responses use LWL’s approved tone, signature format (“[First Name] | [Title]”), and no emojis unless pre-approved.
5.3.3.3 HubSpot logs message timestamp, sender, recipient, and project association.
5.3.4 Resolution
5.3.4.1 Once client acknowledgment or task completion occurs, conversation is marked Closed.
5.3.4.2 Closed SMS threads remain searchable and reportable in HubSpot.
5.4 SCENARIO 3: UNASSIGNED MESSAGE HANDLING
Objective: Manage new or unmatched messages that do not automatically associate with a project or client record.
Process Flow:
5.4.1 Detection
5.4.1.1 HubSpot flags inbound emails or SMS that do not match an existing Contact or Deal.
5.4.1.2 These messages appear in the **Unassigned Conversations** queue.
5.4.2 Review
5.4.2.1 Operations or any authorized user reviews the queue twice daily.
5.4.2.2 If identifiable, the message is manually associated with the correct Contact and Deal record.
5.4.3 Assignment
5.4.3.1 Once associated, HubSpot automatically assigns to the project’s Primary POC.
5.4.3.2 The Primary POC receives notification and continues the conversation as normal.
5.4.4 Closure
5.4.4.1 If determined to be spam or unrelated, any authorized user may close the conversation.
5.4.4.2 Team members should use judgment when closing conversations; if there is any doubt about whether a message might be legitimate, use internal notes to @mention colleagues for input.
5.4.5 Spam Handling
5.4.5.1 Obvious spam or irrelevant communications may be closed by any Standard User or Administrator without requiring escalation or administrative review.
5.4.5.2 Team members should use judgment when closing conversations; if there is any doubt about whether a message might be legitimate, use internal notes to @mention colleagues for input.
Outcome: Every valid client message is captured and assigned through a clear, human-driven process, with shared responsibility for keeping the Unassigned Conversations queue clear.
5.5 Communication Status and History Management
Conversations are classified as Open (requiring LWL action) or Closed (fully resolved). 
5.5.1 Open Conversations: Conversations with Open status appear in the primary inbox view and individual POC work queues. 
5.5.2 Closed Conversations: Conversations marked Closed are removed from the primary inbox view but remain fully accessible in each project's complete communication history. 
5.5.3 Complete Communication History: Every project record must maintain a comprehensive, chronological thread of all written client communications (email, SMS, and internal notes), visible to all authorized users and filterable by date, channel (email/SMS), POC, and status. 
5.5.4 Status Change Authority: POCs must be able to manually change any conversation's status between Open and Closed as needed to reflect operational reality and manage workload. Administrators may modify any conversation status as needed
Purpose: This status-based filtering maintains clarity in daily work and ensures historical completeness while preventing unnecessary inbox clutter. It also supports operational reporting of communication volume and responsiveness across teams and projects.
5.6 Summary
These user scenarios define how Living With Lolo's communications hub will function to ensure every client message is captured, assigned, and resolved with visibility and accountability—enabling LWL to deliver a consistently white-glove client experience.
