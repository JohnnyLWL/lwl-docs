3.0 FUNCTIONAL BUSINESS REQUIREMENTS

3.1 Purpose

The solution provides a unified system where all client-facing email and text message communication can be viewed, managed, and tracked within HubSpot. The configuration uses HubSpot Sales Hub Professional (10 seats) as the central workspace, integrated with Gmail for email and with the HubSpot Marketing Hub Professional (1 seat) with SMS Access Add-On for text messaging.

All inbound and outbound written communication is handled through the HubSpot Conversations Inbox, providing shared visibility and accountability. Voice, voicemail, and Enterprise-tier capabilities remain out of scope for Phase 1. No SLA timers or escalation alerts are implemented. Manual monitoring ensures timely responses through Primary and Backup POC coordination.

3.2 Core Business Functions

This implementation focuses on email, HubSpot-native SMS (text messaging), and internal notes. Voice call handling and voicemail transcription capabilities are explicitly excluded to minimize complexity and control costs.

3.3 Routing & Assignment

3.3.1 POC Assignment Architecture

Each project must have exactly two designated Points of Contact (POCs): one Primary and one Backup. HubSpot serves as the authoritative system for all POC assignments. POC assignments are stored as properties on each HubSpot Deal record and are automatically managed through HubSpot workflow automation based on the project's current phase.

3.3.1.1 POC assignments align with project phase using the phase-to-POC mapping defined in Appendix C.

3.3.1.2 When a new project achieves "Paid" status in Airtable:

Airtable automation triggers webhook to Zapier with Project ID, client contacts, and current phase

Zapier creates new Deal record in HubSpot with phase property populated

HubSpot workflow automatically triggers on "New Deal Created"

Workflow reads phase value and automatically assigns Primary and Backup POCs based on Appendix C mapping

3.3.1.3 When a project phase changes in Airtable:

Airtable automation detects phase field change

Airtable automation triggers webhook to Zapier with Project ID and updated phase

Zapier updates existing Deal record's phase property in HubSpot

HubSpot workflow automatically triggers on "Phase property changed"

Workflow reads new phase value and automatically updates Primary and Backup POC assignments based on Appendix C mapping

3.3.1.4 All POC assignment changes are logged automatically in HubSpot Deal timeline with timestamp and triggering event (phase change, manual override, etc.).

3.3.2 Vacation Flag & Intelligent Routing

3.3.2.1 Vacation Flag Property

Each HubSpot user has an "Out of Office" property (boolean checkbox) that controls routing behavior. When enabled, all new inbound communications assigned to that user are automatically redirected to their designated Backup POC.

3.3.2.2 Routing Logic with Vacation Flag

The system automatically routes all incoming communications using the following logic:

Message arrives at VIP@livingwithlolo.com or shared SMS number

HubSpot identifies sender and associates with project Deal record

System reads Deal's current phase

System reads Primary POC assignment for current phase

System checks Primary POC's "Out of Office" flag: 

If FALSE (not on vacation): Route to Primary POC

If TRUE (on vacation): Route to Backup POC

Assigned POC receives notification per their configured preferences

3.3.2.3 Vacation Flag Management

Each team member is responsible for toggling their own "Out of Office" flag when taking time off

Flag should be enabled on last working day before absence

Flag should be disabled on first working day upon return

Administrators can view and manage vacation flags for all users

Monthly monitoring dashboard identifies flags enabled for >5 consecutive days (detects forgotten toggles)

3.3.2.4 Backup POC Coverage Responsibilities

When serving as Backup POC during a Primary's absence:

Backup POC receives all new inbound communications automatically

Backup POC responds to new messages using HubSpot interface

Active conversations that began before the absence retain their original assignment (conversation ownership persistence per Section 3.3.7)

Backup POC may use internal notes to coordinate with Primary POC if needed

3.3.3 Manual Routing Override

3.3.3.1 Administrators (CEO, Director of Operations, LWL IT Lead) may manually override automated POC assignments on individual Deal records for special circumstances:

Extended leave requiring temporary POC reassignment

VIP client requiring specific POC regardless of phase

Training period for new team member

3.3.3.2 Manual overrides persist until manually reverted or until automated workflow updates POC assignments due to phase change.

3.3.3.3 All manual overrides are logged in Deal timeline with administrator name and timestamp.

3.3.4 Routing Configuration Maintenance

3.3.4.1 The phase-to-POC mapping (Appendix C) is implemented as conditional logic within HubSpot workflow automation.

3.3.4.2 When POC responsibilities change (new hires, role changes, departures), the LWL IT Lead must update the HubSpot workflow mapping within 1 business day.

3.3.4.3 Workflow updates must be tested in HubSpot sandbox environment before production deployment.

3.3.4.4 All workflow mapping changes must be documented in Appendix C with version date and approver signatures.

3.3.5 Manual Reassignment

3.3.5.1 POCs may manually reassign any conversation to another team member at any time. All reassignments are logged automatically in HubSpot for accountability.

3.3.5.2 When reassigned, the new POC receives full ownership of the conversation, including all future client replies and notifications.

3.3.5.3 Email threads remain associated with the same subject line and conversation ID; SMS threads remain associated with the client's phone number.

3.3.5.4 Reassignments are logged automatically in HubSpot for accountability, including original owner, new owner, user performing reassignment, and timestamp.

3.3.5.5 Team members should use internal notes to @mention colleagues when collaboration is needed without transferring ownership.

3.3.5.6 Administrators retain authority to reassign conversations if coverage issues arise or ownership needs clarification.

3.3.6 Conversation Ownership Persistence

3.3.6.1 Once a conversation is created and assigned to a POC, that POC retains ownership of the entire conversation thread (including all future replies) until the conversation is closed or manually reassigned.

3.3.6.2 Project phase changes in Airtable do not trigger reassignment of active conversations. The POC who was assigned when the conversation began retains ownership regardless of phase transitions.

3.3.6.3 NEW conversations (new email subject lines or new SMS threads) created after a phase change will route to the Primary POC for the current phase.

3.3.6.4 Email replies from clients are treated as part of the existing conversation thread and route to the currently assigned POC, not the Primary POC for the current phase.

3.3.7 Default Routing for Unknown Senders

3.3.7.1 Communications (email or SMS) from unrecognized senders appear in HubSpot's "Unassigned Conversations" inbox view for manual review and association with the correct project.

3.3.7.2 The Unassigned Conversations queue operates on a self-service model:

All team members with Standard User or Administrator permissions can view the Unassigned Conversations queue

Any team member may review unassigned communications and associate them with the correct project

Team members are encouraged to proactively check the Unassigned Conversations queue when they recognize client names or project context

3.3.7.3 No automatic notifications are sent for unmatched communications. Team members check the Unassigned Conversations queue proactively as part of their daily workflow.

Unknown senders are typically new leads, vendors, or spam—rarely time-sensitive existing client communications

Team members should check the Unassigned Conversations queue 1-2 times daily during business hours

3.3.7.4 When any team member associates an unmatched communication with a project:

The sender's contact information is linked to that project's Deal record

The conversation is assigned to the project's Primary POC

The Primary POC receives notification of the newly assigned conversation

All future communications from that sender automatically route to the correct project and POC

3.3.7.5 Obvious spam or irrelevant communications may be closed by any Standard User or Administrator without requiring escalation.

LWL's service expectation is that all messages receive acknowledgment within one business day. The vacation flag system ensures continuous POC availability through automated routing to Backup POCs during planned absences.

3.11.4 Synchronization Strategy

3.11.4.1 Event-Driven Synchronization

The solution implements event-driven synchronization triggered by specific business events in Airtable rather than time-based polling:

Trigger 1: New Paid Project

When a project's status changes to "Paid" in Airtable:

Airtable automation triggers webhook to Zapier

Webhook payload contains: Project ID, client contact information, current phase

Zapier creates new Deal record in HubSpot with phase property populated

HubSpot workflow automatically triggers on "New Deal Created"

Workflow reads phase value and assigns Primary and Backup POCs per Appendix C mapping

Trigger 2: Phase Change

When a project's "Phase" field changes in Airtable:

Airtable automation triggers webhook to Zapier

Webhook payload contains: Project ID, updated phase value

Zapier updates existing Deal record's phase property in HubSpot

HubSpot workflow automatically triggers on "Phase property changed"

Workflow reads new phase value and updates Primary and Backup POC assignments per Appendix C mapping

3.11.4.2 Weekly Baseline Sync (Safety Net)

Every Sunday at 6:00 AM Arizona Time, a scheduled Zapier workflow performs a full synchronization of Airtable project data to HubSpot.

This baseline sync serves as a safety net for low message volume operations, ensuring that manual updates are captured even in the absence of webhook triggers.

3.11.4.3 Manual Sync Override

Administrators may manually trigger synchronization of individual projects via Zapier's manual run functionality if immediate sync is required outside of automated triggers.

3.11.5 Error Handling and Reliability

3.11.5.1 All synchronization workflows must include error notifications to administrators (LWL IT Lead and Airtable Administrator) if webhook delivery fails or HubSpot update operations encounter errors.

3.11.5.2 Failed syncs must be retried automatically (up to 3 attempts) before generating administrator alerts.

3.11.5.3 The system must maintain data integrity when temporary synchronization failures occur, with clear procedures for manual reconciliation documented during implementation.

3.11.5.4 Phase Name Validation

Airtable phase values must exactly match (case-sensitive) the phase names defined in Appendix C and configured in HubSpot workflows. Phase name mismatches will cause POC assignment failures.

LWL's Airtable Administrator validates exact phase spelling during Phase 1 Discovery

HubSpot workflows include error logging for unrecognized phase values

Monthly validation checks identify any Deals with unrecognized phase values
