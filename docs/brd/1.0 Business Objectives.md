1.0 BUSINESS OBJECTIVES

1.1 Purpose

The purpose of the Living With Lolo (LWL) Consolidated Client Communications Hub initiative is to deliver a seamless, professional, and elevated client communication experience by centralizing all written client interaction channels — email, text, and internal collaboration notes — into one integrated HubSpot-based workspace. This initiative eliminates fragmented communication and establishes a consistent, brand-aligned point of contact for every client and project. Phase 1 explicitly excludes voice calling, voicemail, and any automated escalation or alert mechanisms, focusing solely on email and SMS channels managed through manual oversight. Clients will be instructed to communicate with LWL only through the shared email and text channels.

The communications hub serves as the client-facing nerve center of the LWL ecosystem, connecting with core operational systems such as Airtable, QuickBooks Online, and Buildertrend. Airtable acts as the authoritative source for project metadata and POC assignments; HubSpot functions as the operational interface for client communications; Gmail remains the enterprise email backbone. Future consideration may include replacements or enhancements to Buildertrend and/or DesignFiles, but these remain out of scope for Phase 1.

1.2 Strategic Objectives

1.3 Desired Business Outcomes

1.3.1 Clients never have to wonder ‘who to contact.’ Every inbound message—email or text—automatically routes to the correct Primary Point of Contact (POC) for that project. When the Primary POC is unavailable, the designated Backup POC manually monitors and responds in HubSpot Conversations.

1.3.2 No communication should go unanswered beyond one business day. Team members check the shared inbox multiple times daily to maintain responsiveness and accountability through manual monitoring.

1.3.3 Everyone at Living With Lolo has full visibility. Any team member can view all client communications (both Open and Closed), filtered by project, phase, or POC—eliminating blind spots and miscommunication.

1.3.4 All communications, including responding to emails and texts, occur within the HubSpot ecosystem. POCs engage clients exclusively through the HubSpot app (desktop, mobile, or web), ensuring no use of personal devices or external accounts.

1.3.5 Project communication is easily filterable and stored long-term. Each email, text, and note is tagged by project and stored in a structured, auditable timeline within HubSpot.

1.3.6 Consistent tone, professionalism, and brand alignment. All direct responses reflect LWL's tone: warm, confident, clear, and high-end.

1.4 Scope of Transformation

This initiative represents more than a software deployment—it is a business capability transformation. The communications hub will:

1.4.1 Replace fragmented tools and manual processes.

1.4.2 Establish a single pane of glass for all client-facing communication.

1.4.3 Enable measurable improvements in responsiveness, accountability, and client satisfaction.

In future phases, this same capability may extend to vendor and/or trade partner communications, completing the connection between design, construction, and operations.

This implementation also serves as LWL's first major integration with HubSpot, laying the groundwork for future capabilities—including potential extensions into marketing automation, SEO management, and performance analytics. At this stage, however, the focus remains squarely on consolidated client communications.

1.5 System Boundaries & Integration Scope

This table defines the role and integration scope for all systems relevant to Living With Lolo's operations during Phase 1:

1.5.1 All integrations operate on a one-way synchronization model from Airtable to HubSpot and from Gmail to HubSpot. HubSpot does not write back to Airtable or Gmail. Event-driven triggers via Airtable webhooks (for new Paid projects and Phase changes) keep HubSpot metadata current. A weekly baseline sync runs every Sunday at 6 a.m. Arizona Time as a safety-net process.

1.5.2 Systems marked "Out of scope" should not influence Phase 1 architectural decisions.

1.5.3 Future integration with Buildertrend or DesignFiles will be evaluated independently in subsequent phases.

1.5.4 Data Integrity and Synchronization Policy
This implementation requires data consistency across Gmail, HubSpot, and Airtable through one-way data flows and event-driven synchronization. The distributed data ownership model, conflict prevention procedures, and integration architecture requirements are defined in Section 4.1. All configuration of these integrations will be documented in the accompanying System Design Document (SDD v1.0).

1.6 System Integration Context

Living With Lolo operates multiple systems that support project delivery and client relationships:

1.6.1 External Project System Integration

The communications hub maintains data consistency with Airtable’s project records through event-driven one-way synchronization of key metadata from Airtable (authoritative source) to HubSpot. Trigger events include “New Paid Project” and “Phase Change.” Required synchronized fields include Project IDs, client contact information, two-tier POC assignments (Primary and Backup), and project phase status. Implementation approach and maintenance responsibilities are defined in Sections 3.11, 7.3.1.7, and 7.3.3.1.1.

1.6.2 Implementation Team Structure

The LWL IT Lead is responsible for HubSpot configuration including routing logic, Gmail synchronization, SMS integration, POC assignment workflow automation, vacation flag configuration, user permissions, and end-user training.

The Airtable Administrator and Integration Architect is responsible for Airtable schema validation, Project ID naming conventions, webhook automation development, Zapier workflow configuration (project metadata only - excludes POC assignments), and ongoing synchronization monitoring.

HubSpot serves as the authoritative system for POC assignments and vacation routing. POC assignments (Primary and Backup per phase) are stored and managed exclusively in HubSpot through automated workflow logic based on project phase. Airtable synchronizes project phase data to HubSpot, which triggers automated POC assignment updates.

Both roles collaborate on field mapping, payload structure, error handling, and post-launch support for the first 90 days after go-live.

Before the HubSpot LWL IT Lead begins Phase 1 Discovery, LWL's Airtable Administrator  will complete the following readiness deliverables:

1.6.3.2 Airtable Schema Validation

Project Status (with "Paid" value defined)

Phase (with all project phases enumerated)

Phase (with all project phases enumerated - exact spelling required for HubSpot workflow integration)

1.6.3.3 Webhook Automation Proof-of-Concept

Build test webhook automation in Airtable sandbox

Successfully trigger webhook to test Zapier catch hook

Demonstrate JSON payload structure (Project ID, client contacts, current phase)

Validate authentication and error handling

Deliverable: Screen recording of successful test webhook with payload visible

1.6.3.4 Integration Architecture Proposa

Document Josh's recommended approach for:

Webhook trigger configuration in Airtable

Zapier workflow structure (event-driven + weekly baseline)

Error handling and notification strategy

Monitoring and maintenance procedures

Identify any technical constraints or limitations

Acceptance Criteria: LWL IT Lead reviews and approves all four deliverables in writing before Phase 1 kickoff occurs.

CRITICAL: The LWL IT Lead's Phase 1 Discovery cannot begin until items 1.6.3.1 and 1.6.3.2 are complete. Items 1.6.3.3 and 1.6.3.4 may be completed during Phase 1 in parallel with LWL IT Lead's discovery work.

Completion of all deliverables under 1.6.3 constitutes Phase 1 readiness and authorization to commence system configuration activities as defined in the System Design Document (SDD v1.0).
